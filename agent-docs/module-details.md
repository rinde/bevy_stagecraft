| `check::suggest` | `WorldSnapshot::take` (reflected resources flattened into field paths, counts per reflected component, UI texts and the states of the widgets they uniquely label, reflected `State`s, `AppCheck::facts`), `suggest_checks` (the diff as `Resource`, `Count`, `InState`, `Shows`/`Not(Shows)`, widget states, `App`/`Not(App)`, each kept only if it loads and holds at the end; fixed order, BTreeMaps only), `NoiseFilter` (default ignores `bevy_*` and this crate; `ignore`/`keep` patterns by short or full path, name without generics, or `prefix*`). | `trace`    | `ScenarioTrace` (`TracePoint`: frame, steps started, finished, `WorldSnapshot`, UI tree as `UiLine`s, tooling left out; `StepTrace` with `TargetTrace`s, `TraceCheck`s and `TraceCaptured`s (name, what was measured, RON value, type name); `before(k)` is the last point with `started <= k`, `after(k)` the first with `started > k` or finished); `step_title` (with the group path in front) and `StepView` (plain data bringing together one step's outcome, targets, captured values, checks, snapshot diff and the points before and after it: the one description `index::trace_html` and the gallery's Trace tab both render) | done |
| `overlay`  | `CursorOverlayPlugin` (the overlay exists only while there is a camera: `maintain_overlay` spawns every `OverlayRoot` the first frame one does, each with a `UiTargetCamera` in its spawn bundle so an app's `Add<Node>` observer never sees an unaimed overlay root, aimed at `OverlayCamera` else `DefaultUiCamera`; it retargets when that camera changes and despawns the roots when it goes): arrow cursor, press ring, held marker, trail and caption strip (`OverlayTheme`, `TargetDescriptions`, `OverlayCamera`), and the pick outlines (`PickHighlight`: the hovered node with a tag naming its best target, the picked one a ring further out); touch: `OverlayFinger(id)`, a filled circle per finger that is down (read from Bevy's `Touches`, which scripted fingers reach), and `OverlayTouchMark` (`TouchMarkKind::{Down, Up}`, age counted in frames, `TOUCH_MARK_FRAMES`) where a finger went down and where it lifted or was cancelled, shrinking and fading; the systems `show_fingers` and `animate_touch_marks` in `OverlaySystems::Update`, the colours `OverlayTheme::{finger, touch_down_mark, touch_up_mark}`; a touch step never moves the arrow; all `Pickable::IGNORE`; added only by the gallery and the recorder. A `CheckpointTaken` message from the session shows as a short flash over the window and a caption line (`checkpoint_text`); while the session is asking for a checkpoint's name (`SessionRecorder::naming`) the line is the prompt instead (`naming_text`, ASCII); the step caption (`describe_step`, `current_step_text`) shows a step's group path, counted in frames. Default marks are ASCII (`PASS`/`FAIL`): the bundled font draws `\u{2714}`/`\u{2718}` as empty boxes | done |
| `recorder` | `RecorderPlugins` (headless app plus the real renderer, every camera retargeted to an `Image`, the synthetic pointer aimed at it) and `Recorder` (per scenario: PNGs at step boundaries and every nth frame, filmstrip, GIF; overall `index.html`, failures first; `Recorder::check` plays the same rendered scenarios and returns `Checked` (`scenarios`, `any_failed`) with no pictures, traces or files). Feature `record`; `Recorder::variants` records every scenario once per variant, one index entry each, `RecorderPlugins::with_scale_factor` (the image has the physical size; the cameras' `ImageRenderTarget`, the synthetic pointer's and each `Screenshot`'s carry the scale factor, or the pointer is on no camera and the picture is black); every recorded scenario is traced (`Recorder::with_noise_filter`, `ScenarioRecording::trace`) and `request_frames` runs after `ScenarioSystems::Trace` so each trace point's frame has a picture; a scenario that does not name the variant is `ScenarioRecording::skipped` and nothing is played or written for it (the index card says `SKIPPED`), which `passed` / `failed` / `Recording::any_failed` keep apart; the recorder also answers screenshot checks (`RecorderSupport` has the `Pictures` and `ScreenshotSettings` resources): `request_check_picture` (`Last`, after `RecorderSystems::Capture`) takes the picture the player wants, reusing the recording's own screenshot of that frame where `request_frames` took one (Bevy keeps one screenshot per target per frame), `store_check_picture` hands it over, and `hide_overlay_for_picture` (`PostUpdate`, before visibility propagation) hides every `OverlayRoot` for it, `show_overlay_again` (`First`) puts it back; a world without `Pictures` (headless, gallery) skips screenshot checks | done |
| `capture`  | `Frame` (RGBA pixels), PNG and GIF encoding, filmstrip drawing (marks and numbers drawn from shapes, no font). Feature `record` | done |
| `index`    | The per-scenario files and `index.html`. Feature `record`; `trace.html` per traced scenario (`trace_html`: per step the failure, targets, checks, pictures before and after, snapshot diff, UI tree and snapshot; `<details id="step-k">`; it renders `StepView`s), and failed cards list their steps linking to it (a step in a group is titled with its path); `write_scenario` copies the baseline, actual and diff pictures of a screenshot check that created or mismatched into the scenario's `snapshots/` (`SNAPSHOT_DIR`) and the card links them | done |
| `session`  | `SessionPlugin`, `SessionRecorder`, `session::start`/`stop`/`checkpoint`/`add_check`: real input logged against a frame counter at 1/60 s, turned into steps on stop (`steps_from_events`, `read_log` (also says where each checkpoint falls): RDP-simplified `Glide`s, `Click`, `Drag`, `Tap`, real touch (`RecordedKind::Touch { finger, phase, position, target }`, fingers numbered from 0 by the lowest free number, not the system's touch id; the recorder reads `TouchInput` of the primary window, merges moves of one frame, ignores a finger that came down before the session and lifts the ones still down on stop) as `TouchTap` (finger 0, in place), `TouchDrag` (finger 0, straight) or spelt out as `TouchDown`, `TouchMove`s at the RDP vertices (a `TouchMove` takes one frame, so waits sit between) and `TouchUp`/`TouchCancel`, with `with_finger` for other fingers; a gesture with other input logged in between is emitted event by event; touch never moves the script's mouse pointer, shortened idle `Wait`s (a step holds at most `u16::MAX` frames, so a longer pause is several `Wait`s, a longer `Glide` several legs through points on the straight line, a longer `Drag` a move, press, `Glide`s and release; the emitter's clock always equals the frames the steps play: `emit_wait`, `emit_glide`, `emit_drag`) (shortened further before the pointer goes to a locator target: `StepOptions::widget_idle_frames` / `widget_idle_wait`, as playback waits for it), clicks named by the first of `target_alternatives` for the widget with a role (not a slider) or text under them, a `RecordedKind::Check` as a `Check` step where it was chosen; `RecordedKind::Key` carries the text the key produced, and consecutive keys that typed text, each released within `hold_frames`, merge into one `Type` step, never Enter, Tab or Backspace nor a Ctrl, Alt or Super chord). The setup (`AppSetup::capture`), the view (`AppView::current`) and app targets for clicks on no nameable widget (`AppTarget::at`) come from the app's reflected types; `SessionHooks` holds the `NoiseFilter` and the checkpoint key, F8 by default. Snapshots of the world on start, at each checkpoint and on stop; a checkpoint can be named (`Checkpoint::name`): after the key a prompt takes the primary window's keys (`MAX_NAME_CHARS` letters; Enter keeps, Escape skips, Backspace edits; a mouse press, the next checkpoint or stop keeps what was typed; their releases are swallowed too; `SessionHooks::checkpoint_names(false)` turns it off), or `checkpoint_named(world, name)` names it from code, and the steps since the checkpoint before, with its own `Check` steps, become a `Step::Group` called that (`with_checks` builds it, so `save_checks` keeps the groups); each checkpoint's suggested checks (diffed against the checkpoint before, or the start) become `Check` steps there and `SavedSession::checkpoints`, the last diff becomes the script's `expect` and `SavedSession::candidates`; `save_expect` / `save_checks` rewrite the file with the kept ones. The checkpoint key is taken out of the primary window's `KeyboardInput` and `WindowEvent` messages before `InputSystems` while recording (`SessionSystems::Checkpoint`), so the app never sees it; each checkpoint writes a `CheckpointTaken` message the overlay shows. Submodules: `log` (pure log to steps), `hooks`, `target` (what a click names, through `target_alternatives`). Not feature-gated; the gallery's **Record** button drives it | done |
| `save`     | A checkpoint saved as a setup for other scenarios (`Setup::Scene`). `save_setup(world, dir, stem, noise)` first tries the app's own `AppSetup::capture` (a returned setup is the result, nothing written by the crate), else writes `{stem}.scene.ron` (the stem is numbered, `stem-2`, when `dir` already holds any `{stem}.<extension>` other than the scenario's own `{stem}.ron`, so neither a saved world nor an app's own `capture` files are overwritten) holding the app's reflected resources and entities as a Bevy `DynamicWorld` (feature `bevy_world_serialization`); `scene_ron` / `load_scene_ron` / `load_scene_file` (resources replaced, entities added, handles through the `AssetServer` if any). Left out: types the `NoiseFilter` ignores (default `bevy_*` and this crate), UI nodes, cameras, windows and their descendants, `NotUnderTest`, entities left empty. Deterministic: resources and components sorted by type path, entities by id (inside one value the order is its own, so a `HashMap` field is written in hash order). `SCENE_SUFFIX`, `is_scene_file`, `SaveError`, `SavedSetup`. Re-exported at the crate root | done |
| `gallery`  | `GalleryPlugin` (feature `gallery`): the app in the primary window, a second `Scenarios` window with its own UI camera, placed directly left of the app window (macOS automatic window tabbing is turned off so the two never become tabs) (catalogue, play/pause, step frame/step, restart, speed, loop, Take over, Export, Save as setup (`GalleryAction::SaveAsSetup`: `save::save_setup` into the export directory, named for the selected scenario, allowed while recording, paused, taken over or finished but not while a script plays (`GalleryState::is_script_playing` / `can_save_as_setup`: the button is dimmed and a click only says "Pause the script to save it as a setup", as the buttons a recording refuses say "Stop recording first"); the status line says where), Record, New (`NewEmpty`: reset hook, nothing selected, then record; `NewFromCurrent`: the app as it is, then record), Pick, live checks). Submodules: `catalogue` (`Gallery`, `GalleryEntry`; `Gallery::directory` adds a group of a directory's `.ron` files and watches it, `prepare_files` is what is done to every scenario read from a file, on reloads too; an entry keeps its `source`, `error` (why the file does not load now) and `is_unloaded` (no version ever loaded: a placeholder, refused by `select`, a failure in run-all); `poll_files` compares modification time and length and returns `Reload::{Changed, Added}`; polling, no file-watcher dependency), `watch` (`reload_changed_files`: every `WATCH_INTERVAL` updates, not during run-all; a good reload forgets that entry's results and requests `Restart` if it is selected and not recording; an added entry shifts the selection and results by `GalleryState::insert_entry`; `ui::rebuild_catalogue` respawns the catalogue on `Gallery::revision`, an error shown under the entry), `state` (`GalleryState`, `GalleryAction`, `Speed`, `Picking`, `Suggestions`: the checklists shown when **Record** stops, one per checkpoint and one for the end, each click on a row rewriting the file's `Check` steps at that checkpoint or its `expect`; the wheel scrolls them while hovered), `control` (requests and pacing, drives the player through `advance_world`; `release_held` (on Take over, select, clear and record) releases the buttons and keys the script holds and also cancels every finger it still holds (`touch_cancel` from `Touches`), so the overlay marks it and the app sees a cancel; a picked check goes to `session::add_check` while recording, else to the selected scenario's expect and the running player), `input` (drains real input aimed at the primary window while a script plays or pick mode is on, touching messages only when something is to be removed so kept ones are not replayed, counts pick clicks, bridges the Scenarios window to its own pointer, asserts and restores the cursor, shows the app no cursor while the person picks), `pick` (pick mode: outlines the node under the real cursor through `PickHighlight` and picks it on a click), `ui` (also the pick panel: targets, checks that hold, app check forms). The Scenarios window shares its height between the catalogue and the details panel (`ui::share_room`, set each frame by `split_panels` from the previous layout): half each, unless one needs less than half, then the other gets the rest, and neither gets under 20%. `Gallery::variants` and `GalleryAction::SelectVariant(i)` (a **Variant** button row when there are several; results are kept per entry and variant as `ScenarioResult::{Passed, Failed, Skipped}`; run-all plays every entry in every variant and skips an entry whose scenario does not name the variant, reporting it as `SKIP` in the run report rather than a failure; the primary window's size and scale factor of before the first variant are put back where a scenario sets none; Export and the pick checks still use the catalogue's scenario as written). `NotUnderTest` (in `targets`) hides gallery and overlay UI from target lookups; `GalleryAction::JumpTo(k)` / `Control::JumpTo` (the step list in the details panel, whose lines and the checks' show each step's group path, numbered flat): restart, `pause_before(Some(k))`, one script frame per update while jumping (`GalleryState::jumping_to`), then paused; refused while recording. The **Trace** tab (`GalleryTab`, `GalleryAction::ShowTab`) beside the scenario view in the details panel: tracing is on for every run except run-all; the complete trace is stored in `GalleryState` when a run ends (kept across jumps, cleared on `Select` and `Restart`; the tab reads `state.trace()` else the player's live one); **Follow** (`ToggleTraceFollow`) shows the step the script is at, else once over the first failing step or the last; `InspectStep(k)` looks at one (turning Follow off, as does a jump, which also shows the Before world); `ShowTraceWorld` picks the UI tree before or after the step; the tab redraws on a cheap `TraceKey` (not every frame) and on `revision`; picking and the suggestion checklists take precedence over it. The gallery's trace is taken with `NoiseFilter::nothing()` and the tab filters the *changes* it lists when drawing (`StepView::new` takes the filter; `StepView::hidden` holds what it leaves out; the recorder passes `trace.filter()`, so `trace.html` is as before): `GalleryState::noise` starts as the filter of the session hooks (`GalleryPlugin::with_session_hooks`), `GalleryAction::ToggleType(i)` hides or shows the type of the i-th change line (`noise_types`, rewritten when the tab is drawn), `UseNoise(NoisePreset::{App, Everything})`, `ToggleHiddenChanges`; all are accepted at any time, last for the gallery session across scenarios, and touch the Trace tab only (not `trace.html`, recording suggestions or pick mode); the tab ends with `As code:` (`NoiseFilter::to_code`) | done |
