| `headless` | `HeadlessPlugins`: a real Bevy app and UI with no GPU or display (virtual primary window, fixed 1/60 s time; `with_scale_factor`: the window keeps its logical size, its physical size is that times the factor, `DEFAULT_SCALE_FACTOR` = 1) | done |
| `input`    | `SyntheticInput`: queued mouse and keyboard input, drained in `PreUpdate` into Bevy's input messages and `PointerInput`; `type_character` queues a character as a `Character` event (Shift down, logical key with its text, release, Shift up, all in one frame); `keystroke` / `Keystroke` is the US-layout mapping from a character to a key and whether Shift is held; modifier key events carry `Key::Shift` etc. so `ButtonInput<Key>` sees them as text fields do; touch (`touch_down` / `touch_move` / `touch_up` / `touch_cancel`, `SyntheticEvent::Touch`) writes `TouchInput` and `PointerInput` for `PointerId::Touch(id)` directly (Bevy's touch picking reads window events a headless app never has), spawning the pointer on `Started`, with the `Last` system `despawn_ended_touch_pointers`; touch never moves the mouse or `Hovered` | done |
| `scenario` | `Scenario` builder (the app's setup and view, `app_setup` / `scene_setup` / `app_view`, which a file holds; `with_base_dir` / `base_dir` (where a setup that names a file looks for it; `load_ron_file` sets the file's directory); `with_group_path` / `GROUP_SEPARATOR` (ASCII `" > "`, the bundled font has no `›`) put the path before a line; `Step::group`; with `Type { text, into }` / `type_text` / `type_into`: one character per frame through `SyntheticInput`, `into` clicks its target first, file form `Type(text: "..", into: ..)`; `MoveBurst([positions])` / `move_burst`: several pointer moves in one frame, for a high-rate mouse; `Capture { name, value: Measure }` / `Step::capture` (reads the world and keeps it under a name for later comparisons, takes no frame; `inner`, `waits_for_target`; touch steps `TouchDown`/`TouchMove`/`TouchUp`/`TouchCancel` (`finger`, 0 left out of a file, `with_finger`), `TouchTap` (down, up the next frame: Bevy clicks only an entity hovered the frame before) and `TouchDrag` (`frames + 2`); the ones that aim at a target wait and take `Timeout`/`Force`), `Modifiers` (serde form is a list, `[Ctrl, Shift]`); `to_script` / `from_script` / `from_ron` / `to_ron` | done |
| `check`    | `Check`, a check as data (every check is; no check is a closure): `App` (the app's own check: a value of its one `#[reflect(AppCheck)]` enum, found by Bevy's automatic registration; `AppCheckValue` keeps a file's payload as raw RON until the script loads, reads it with `TypedReflectDeserializer` and writes it with `TypedReflectSerializer`), `Shows`, `Hovered`, `Tree { of, matches }` (the UI below a node as indented lines of role, label and states, an inline image or box (`InlineImage`, `InlineBox`) as an `image` or `inline-box` line under its text, and never read as text itself, a text input also `= "value"`, matched partially: the expected tree lists only what matters, siblings may be left out, their order must hold; a mismatch is a `-`/`+` line diff, whose descent shares pair results through a private `Matcher` memo (one pass over the pairs, not one per level; the first-pass match stays uncached); the text is read at load time; submodule `tree`; `tree_snapshot` at the crate root, also the last of the checks pick mode offers), the reflected built-ins `Count`, `Resource`, `Component`, `InState` (types by short type path, fields by reflect path, values as raw RON read with `TypedReflectDeserializer`), `Screenshot { name, of: Option<Target>, tolerance: Tolerance }` (`Check::screenshot` / `screenshot_of` / `with_tolerance`: the frame, or the target's node rectangle (the upright bounding box, in whole physical pixels, of its box under the complete `UiGlobalTransform`, so a quarter turn swaps width and height and a skewed or turned node includes the corners' surroundings; clipped to the picture), against the baseline `<base_dir>/<slug of the scenario name>/<name>.png`, see submodule `screenshot`), the widget states `Disabled`, `Checked`, `Selected` (also a `Tab` its list's `SelectedTab` names), `Pressed`, `Focused`, `Visible` (about the named node itself, never the widget above it: a hidden list inside a visible `Selectable` row is not `Visible`; the other states read the nearest widget at or above the node, `widget::widget`), `OnTop` (about the named node itself, as `Visible`, except that a text label (a node with `Text`) stands for its widget, so a label still finds its button: `widget::painted_subject`; painted topmost at the node's middle by `UiStack` order, ignoring `Pickable`, where the actionability wait honours it; only nodes that paint cover: `targets::actionable::painted_topmost`), `Exists`, `TextOf` (of a `TextInput`: its `EditableText` value, not its label; `Shows` finds a value too), and `Not`, `All`, `Any`, `Within` (polled by the player frame by frame; `Check::poll` gives an `Option<Outcome>`, and the crate-private `Verdict::Unavailable` is a check that cannot run here, a screenshot without the recorder, which `Not`/`Within` pass through and which is `Outcome::Skipped`); typed builders `CountOf`, `FieldOf`; `Comparison`, `TextMatch`, `Value` (a literal, or `Value::captured(name)` / `.plus(n)`: a value a `Capture` step took, written `Captured("x")` (the positional form takes no offset) or `Captured(name: "x", plus: 3)` (a positional name with a named `plus` is not RON); the long form refuses unknown keys, anything starting `Captured(` is read as a capture so an app enum variant of that name cannot be a literal; resolved to a literal with `Resolved { from, ron }` just before a comparison, so a failure reads ``... expected Captured("x") = 2``; a whole captured integer stays whole and is added exactly as `i128`, anything else as `f64`; `Value` and `Comparison` are `Eq` because an offset is always finite); `Measure` (private submodule `capture`: what `Capture` reads, `Count`/`Resource`/`Component` as the checks read them; `Measure::count::<C>()`, `resource::<R>(path)`, `component::<C>(target, path)`, load-time `problem`, run-time `read` giving a crate-private `CapturedValue` of RON text and type name; `CapturedValues` is the player's per-run store, passed to `Check::poll`, never a world resource; `Check::captured_names`); `Unit` (`Physical` by default, or `Logical`: a `Resource(..)` or `Component(..)` check and the matching `Measure` read a physical number as logical, divided by the primary window's scale factor, and a logical value a `Capture` took feeds a later check; the builder is `.logical()`, and a file writes `unit: Logical`); `AppCheck` (with the optional `facts`, an associated fn with `Self: Sized`), `ReflectAppCheck` (written by hand, not with `#[reflect_trait]`: it holds the cast to `dyn AppCheck` and a function pointer to the type's `facts`); `AppCheckValue` and the variant listing are the generic ones in `extension`. A check is read from RON whole (`RawValue`) so values keep their spelling; the serde form goes through a private mirror enum so no derived functions are public; a bare name, `Named(..)` or `Custom(..)` in a file is refused saying to write `App(..)`, and the old `State(..)` saying to check a reflected resource; a check that cannot run fails even inside `Not`. Submodules: `screenshot` (`Tolerance` (`colour` per channel, default 2, and `pixels` share, default 0; file form `tolerance: (colour: .., pixels: ..)`), `ScreenshotSettings` (`update`, from `RIN_UPDATE_SNAPSHOTS`), `ScreenshotRecord` / `ScreenshotResult` (`Matched`, `Created`, `Updated`, `Mismatch { actual, diff }`; in `ScenarioReport::screenshots`, re-exported at the crate root); the crate-private `Pictures` resource is the hand-over between the player, which asks for a picture before polling a check that holds a `Screenshot` (`prepare`, waiting frames that do not count as the check's `Within` wait) and the recorder, which answers; the pure compare, crop and diff code is ungated, PNG encode and decode need feature `record`; a missing baseline is written and fails, a mismatch writes `.diagnostics/<name>.actual.png` and `.diagnostics/<name>.diff.png` in the baseline directory (a name may not start with `.`, so no baseline can collide; old files beside the baselines are never touched) and removes them on a match, update mode rewrites the baseline; the baseline directory is `directory_name(scenario name)`), `app`, `value`, `reflect` (type and field lookup, close-name suggestions, load-time validation), `widget`, `tree` (snapshot of a node's UI tree, the expected-tree parser, the partial matcher and the diff), `suggest` (public, see its own row) | done |
| `annotation` | `Scenario::tags` / `tag_names`, `skip` / `fixme` / `should_fail` (reasons; file fields `tags`, `skip`, `fixme`, `should_fail`, only added forms of format 3) and the accessors `skip_reason`, `fixme_reason`, `should_fail_reason`, `disabled` (`Disabled::{Skip, Fixme}`, skip first). `TagFilter` (`parse`, `from_env` = `RIN_SCENARIO_TAGS` = `TAGS_ENV`, `matches`: no forbidden tag, and one required tag if any: `bridge,-slow`). Consumers: `files::run_ron_tagged` (a scenario outside the filter is not listed; skip/fixme is `FileOutcome::Disabled`, printed `ignored, ..`, apart from variant `skipped`; `FileResult::should_fail` flips `passed`, failing with a hint when it passes), `Recorder::with_tag_filter` (`ScenarioRecording::{tags, disabled, should_fail}`; the index dims skipped/fixme cards with the reason, lists them last, flips should_fail), the gallery (`Gallery::tags`, `GalleryAction::SelectTag`, `GalleryState::tag`, `GalleryPlugin::with_tag`; a **Tag** row, `ui::filter_entries` hides other entries, disabled entries are `ScenarioResult::Skipped` and dimmed with the reason, run-all skips them and those outside the tag, and flips `should_fail` outcomes) | done |
| `extension` | The app's extension points as reflected enums: `AppSetup` (`build`; optional `capture` for recordings), `AppView` (`arrange`; optional `current`), `AppTarget` (`resolve`; optional `at` for recordings and pick mode), each with hand-written type data (`ReflectAppSetup`, `ReflectAppView`, `ReflectAppTarget`: the cast and a function pointer to the associated fn, as `ReflectAppCheck`). `Extension` names the four points (checks included); `AppValue<K>` (aliases `AppSetupValue`, `AppViewValue`, `AppTargetValue`, `AppCheckValue`) keeps a file's payload as raw RON until the script loads, reads it with `TypedReflectDeserializer` (and every `Target` inside it, so an app target in an app check is checked too) and writes it with `TypedReflectSerializer`; a value built from RON in Rust is typed against the world's registry when used. It is an opaque `Reflect` type, as is `Target` itself. `Setup` (the script's `setup: App(..)` or the built-in `setup: Scene("x.scene.ron")`, a world saved by `save`; other forms refused with a hint) and `View` (`view: App(..)`), `app_type` / `AppType` / `AppVariant` / `AppField` (variants and field types, for forms), `SeveralAppTypes`. One type per point: two is a load error naming both. An `AppSetup` that queues BSN scenes needs no wait of its own: the player holds the first step until they are loaded (see `player`) | done |
| `script`   | `Script` (the serde data model; writes `format_version` 3, reads 1 to 3; optional `action_timeout` and `scale_factor` (finite and above zero, else `LoadError::Invalid`) and `variants` (the variant names the scenario runs in; a runner skips it elsewhere); a `Timeout(..)`/`Force(..)` around any other step is a `LoadError::Invalid`; a `Group(name: .., steps: [..])` only adds a form, an empty or blank name is a `LoadError::Invalid`, and every error inside one carries the group path in `used_by`; `Capture` is only a new form, so also version 3: a check using a name no earlier `Capture` took is a `LoadError::BadCheck`, `expect` checks may use any name captured in the steps, a name captured twice a `LoadError::Invalid`, and a measurement of an unknown type or field the usual `UnknownType`/`UnknownPath` with suggestions), `Setup` and `View` (re-exported from `extension`), `Registry` (only `types`: the type registry reflected checks are validated against and every value inside `App(..)` is typed against when a script loads; the default holds every type that derives `Reflect`; no named setups, views or target resolvers), `LoadError` (unknown types and fields name the step and suggest close names; `expect_state` is refused with a hint; `BadAppValue` names the extension point and where, and lists the variants; `SeveralAppTypes` names them all; `NoAppType` says how to declare one; the old `Named(..)`/`File(..)` setups, a view's bare name and `Custom(resolver: ..)` targets are refused with a hint saying to write `App(..)`), `export_ron` | done |
| `files`    | `run_ron_tests`: a `harness = false` runner turning every `.ron` file in a directory into one test (`*.scene.ron` files are saved worlds and are skipped by `ron_files`; `load_ron_file` gives the scenario its file's directory as `base_dir`); `run_ron_tests_with_variants` / `run_ron_variants` play each file once per `Variant`, as the test `file [variant]` (`FileResult::variant`); a file that names the variants it runs in is `FileOutcome::Skipped` in the others, reported as `skipped` apart from `failed` and counted as passed (`FileResult::skipped`); a file whose app panics fails (the player catches the panic as a failed step) and the runner goes on with the next file | done |
| `variant`  | `Variant`: a runner's environment for a scenario, not part of it (Playwright projects): a name, optionally a window size (logical), a scale factor, a rem size (`rem_size`: Bevy's `RemSize`, set before the scenario's setup by the crate-private `Scenario::fit_rem_size` and not in the script; `run_in` puts the app's back afterwards, the gallery restores it through `GalleryState::original_rem`, the recorder's app is fresh; finite and above zero, else `LoadError::Invalid`; like a scale factor it leaves the logical window alone, so a `Screen` target or `MoveBurst` stays valid; the overlay's and gallery's text is `FontSize::Px` and does not follow it), and an app setup or view that replace the scenario's own (its setup and view closures still run after). `apply` (the scenario as the variant runs it, named `label` = `scenario [variant]`, or the plain name for the default one), crate-private `problem` / `varied` (the runners use them to make a refused variant a failed setup rather than an abort). `is_default` = nothing set. A step that aims at `Target::Screen` or a `MoveBurst` (also inside `Timeout`, `Force`, `Within`, `Nth`, and either in any `Group`, found through `flatten`) is in logical pixels and runs wherever the logical window is unchanged: a scale factor, a setup or a view is fine, and only a window-size change is `LoadError::Invalid`, naming the steps with their group paths. `skips` / `DEFAULT_VARIANT_NAME`: a scenario that names the variants it runs in (`Scenario::variants` / `variant_names`, the file's `variants: [..]`, `default` for the default one) is skipped elsewhere. A runner's variant list is exactly what runs: list `Variant::default()` to cover the scenario as written | done |
| `player`   | `ScenarioPlayerPlugin`: plays a scenario through `SyntheticInput` one frame per update into the `ScenarioReport` resource; an action on a target that names a widget (`MoveTo`, `Glide`, `Drag`, and a `Click`/`Press` right after a move to a widget, which checks that widget) waits frame by frame until the target is actionable (`targets::actionable`), up to the step's or scenario's timeout, then fails naming the first condition that did not hold; an ambiguous or non-UI target fails at once; `Force(..)` skips the checks and the hover check; a waiting action is not at a step boundary; a check that waits (`Check::Within`, also in the expect list) is polled once per frame until it settles; touch steps keep each finger's position in `Running::touches` (a step on a finger in the wrong state fails at once); `Scenario::run_headless` / `run_in` (which first gives the app's primary window the scenario's `window_size` and `scale_factor` where it sets them, and leaves the window alone where it does not); before the first step the player waits (always on, no option, frames counted, at most the scenario's action timeout) until every `ScenePatch` / `SceneListPatch` asset is resolved, which is also when `bevy_scene` applies it (`unready_scenes`; feature `bevy_scene` is in the curated Bevy list for it; `Setup::Scene` and `World::spawn_scene` leave nothing unresolved), else the report has a `setup_failure` naming the assets it waits for (`scenes not ready after N frames: ..`) and no step plays; setup that fails (`AppSetup::build` returns an error) makes a finished report with `setup_failure` set and every step skipped (`ScenarioPlayer::start_after_setup`); the `Last` system `trace_point` (`ScenarioSystems::Trace`) takes a `TracePoint` at each step boundary where a later step became due, and at the end, when `enable_trace(filter)` is on; the player plays `flatten(script)`, so a `Group` is no step of its own (`expand` ignores one) and each `StepRecord` keeps its `group` path, which `failures()` puts in front of the line; the player records each step's targets, captured values and checks into the `ScenarioTrace`; a `Capture` step reads the world in `expand` (`Running::captures`, passed to every `Check::poll`, expects included) and a read that fails aborts the script naming the capture; a panic in the app (an error of severity `Panic` reaching the `FallbackErrorHandler`) fails the step last started and aborts the script like any failed step: the player installs the crate-private `catch` handler while a scenario is active (`First` system `sync_error_handler`, also called by `run_in` around its loop) and restores the app's own after, `fail_caught_errors` in `Last` reads what the handler kept (a thread local, so parallel tests stay apart; other severities and other threads go to Bevy's default handler); `Scenario::run_in_traced` / `run_headless_traced`; `Outcome::Skipped` is also a check that could not run here (a screenshot without a renderer): `ScenarioReport::passed` fails on a `Fail` check only, steps stay strict, and `ScenarioReport::screenshots` keeps each screenshot check's files; before polling a check that holds a screenshot the player waits for the recorder's picture (`Pictures`, reset in `begin`); `pause_before(Some(k))` halts inside `advance_frame` before step k's ops are expanded and takes the frame it began back (`report.frames -= 1`), so the landed frame and world equal the trace's `before(k)`; `halted()` | done |
